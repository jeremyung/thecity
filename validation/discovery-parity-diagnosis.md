# Native/WASM discovery parity diagnosis

The 206 ordered mismatches start after the descriptor inputs have been formed. They are not caused by capture, face tracing, face choice, target ranking, or normalized descriptor inputs.

I added `scripts/diagnose-discovery-parity.mjs`, which advances the public `AccessDiscovery` WASM job, inspects its saved stage checkpoints, and compares the final descriptor-stage inputs with the frozen native references. On the authoritative save `validation/early-reservation-wasm-87231-save.json` (SHA-256 `f5aecc3530a8607f115a352fe1caef73bdbcafaefd23d0d53410bdea9610aa2e`), it confirms exact Float32-bit equality for the selected face identity and polygon, all six sorted targets, all 11 host records, all 160 node records, and all 1,107 sorted/deduplicated parcel envelopes. Thus the first observable divergence is descriptor endpoint generation, downstream of identical inputs. The detailed machine-readable result is `validation/discovery-parity-diagnosis.json`.

The final sequences both contain 2,069 descriptors and have the same count for every `(host_id, host_t)` group. Their exact tuple-set intersection is 1,866; every WASM endpoint has a native endpoint at the same host and split whose Euclidean difference is at most `0.000036 m`. The reported 38.748 m maximum is an index-by-index comparison artifact: a few nearly tied endpoints exchange order, so unrelated rows appear at the same index. There is no evidence here of missing geometry candidates or a materially different route.

The likely numerical source is the platform math in heading construction: `atan2`, `asin`, `sin`, and `cos` in `DescriptorSearch::advance_target` and `advance_tangent` (`engine/src/access_descriptor_search.rs`, around lines 976–1000 and 1157–1177). The offline reference uses the corresponding angle path in `access_candidates.rs` around lines 318–323 and 383–391. Native and wasm32 can use different `f32` transcendental implementations, producing tiny endpoint differences; lexicographic endpoint ordering then amplifies those into a handful of large positional comparisons. This is a code-based diagnosis: the available golden stores final outputs, not intermediate headings, so it does not identify which individual transcendental call first differs.

A concrete next fix is to replace the angle round-trip with one shared vector-rotation helper used by both descriptor implementations. Given normalized `(dx, dz)` and `s = clearance / distance`, compute `c = sqrt(max(0, 1 - s*s))`, then rotate directly as `(dx*c - dz*s, dx*s + dz*c)` (and the opposite sign for the other side). For obstacle tangents, use the same formula with the clearance radius. This removes `atan2`/`asin`/`sin`/`cos` from candidate headings. If exact parity still differs, make the length calculation used by that helper explicit and identical on both targets rather than relying on platform `hypot`.

That change will alter native golden bits and may reorder close candidates, so it should be an intentional geometry update: test the helper’s cardinal and oblique vectors on native and WASM, then compare the two targets directly and regenerate the frozen reference only after both outputs agree. Do not loosen the current exact comparison or replace the current reference with the WASM output alone.
