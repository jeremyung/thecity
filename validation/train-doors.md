# Train doors — 2026-10-11

## Implemented

The engine derives terminal ID and opening fraction from the existing dwell state.
Station dwell is 220 ticks; gateway dwell is 180. Opening and closing take 20 ticks
each at 20 Hz. Boarding occurs only while fully open; alighting is deferred until
that boundary. Boarding cadence changed from four to three ticks so the existing
48-passenger capacity remains reachable. Quiet-hour holds keep doors closed.
No new persisted phase or backward-save migration was added.

The commuter kit has actual wall apertures, jambs and a floor, with paired leaves
sliding into sidewall pockets. Four shared material batches instance 36 leaves per
three-car trainset, capped at eight trainsets. Platform frames select the opening
side; the opposite side stays closed. Moving away from the stop clears stale open
poses. Actor picking includes the door instances.

## Remaining limits

The initial 500 ms world-snapshot door interpolation has been replaced by a compact
movement-channel payload in protocol v4. It shares position interpolation and
cannot be rewound by a later coarse world snapshot. First packets restore the
saved phase immediately. This removes the separate door clock; it does not prove
full passenger choreography or visual motion acceptance. No sustained opening/
closing motion recording has yet been accepted.

Passengers do not yet approach individual doors; interiors and seating are absent.
Curved-route articulation, streetcars, distinct ground-rail infrastructure and
reference-level artistic acceptance remain open. Keep this bounded behavior change
separate from those future rail families.

## Synchronized presentation follow-up

Concrete deficiency: the original separate snapshot interpolation could snap a
closing door at departure. The bounded correction publishes up to eight stride-3
train tuples (96 bytes) with movement, retaining the existing movement buffer pool.
Rust snapshot and compact export share one phase function. Renderer uses the same
interpolation fraction as positions and ignores coarse door updates after bootstrap.
No new simulation phases, geometry changes or save migration were introduced.
