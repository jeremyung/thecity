# Road split WASM profile

The opt-in profiler measured the atomic split against restored cap fixtures with Node.js v26.7.0 on Darwin arm64. Each fixture begins with 4,999 roads and 2,000 travelers; the affected actor's 127-node route grows to the 128-node limit. Five warmups preceded 25 samples per fixture.

| Fixture | Nodes before split | p50 | p95 | Max |
| --- | ---: | ---: | ---: | ---: |
| Detached geometry, 1 affected traveler | 9,993 | 2.390 ms | 2.517 ms | 2.526 ms |
| Connected geometry, 1 affected traveler | 5,000 | 3.678 ms | 7.183 ms | 17.706 ms |
| Connected geometry, all 2,000 affected | 5,000 | 3.694 ms | 3.791 ms | 3.812 ms |

The timed interval is the `CityEngine.split_open_road` WASM call, including its JavaScript/WASM boundary and serialization of the small split result. Restoring each engine, parsing state, and serializing the post-split save are outside the interval. This is a Node WASM measurement, not browser, worker, or frame timing. The reported p95 uses the nearest-rank selection used by the harness.

All cases passed checks that the split adds one road, inserts the node at the requested midpoint, preserves every traveler position, and rewrites each route containing the host edge by inserting the split node at every matching adjacency. Unaffected route topology stayed identical, and each post-split save restored canonically. The many-affected case remapped 2,000 routes. Endpoint-adjacent rejection left the save unchanged. A restore-valid 128-node route traversing the host also triggered a late 129-node expansion rejection with unchanged saved state. The fixture exporter validates the all-affected city before writing it. Exact results and the WASM hash are in [road-split-wasm-profile.json](road-split-wasm-profile.json).

To reproduce, export the fixtures with the native opt-in test, build the profiling-only module, then run the Node harness:

```sh
EXPORT_ROAD_SPLIT_PROFILE=1 ROAD_SPLIT_PROFILE_OUTPUT=/tmp/road-split-profile-stress.json node scripts/test-engine.mjs --release road_split_profile -- --ignored --nocapture
EXPORT_ROAD_SPLIT_PROFILE=1 ROAD_SPLIT_PROFILE_CONNECTED=1 ROAD_SPLIT_PROFILE_OUTPUT=/tmp/road-split-profile-connected.json node scripts/test-engine.mjs --release road_split_profile -- --ignored --nocapture
ROAD_SPLIT_PROFILE_ALL_AFFECTED=1 EXPORT_ROAD_SPLIT_PROFILE=1 ROAD_SPLIT_PROFILE_CONNECTED=1 ROAD_SPLIT_PROFILE_OUTPUT=/tmp/road-split-profile-all-affected.json node scripts/test-engine.mjs --release road_split_profile -- --ignored --nocapture
npm run wasm -- --profiling
node scripts/profile-road-split-wasm.mjs
```

The profiling-only WASM files are emitted to `.tools/wasm-profiling`; the production WASM output is unchanged. Fixture JSON is written under `/tmp` and is generated by the existing opt-in Rust fixture exporter.

The all-affected mode is opt-in; ordinary stress fixtures retain the previous one-affected-actor route mix. The measured cases do not establish total simulation tick cost or browser/worker timing, so use them as a bounded synchronous split profile rather than a production frame guarantee.
